# Data notes (generated)

This file is regenerated by `build.py` on every run and reflects the actual
row counts from *this* run -- DC's crash data is live and grows over time, so
these numbers will drift from whatever is quoted in the top-level README or
any post that links here. See `../README.md` for the human-written overview.

Built from `data/raw/crash_details_table.csv` (DC MPD person-level crash
detail extract, fetched via `fetch_crash_data.py`) joined against DDOT's
"Crashes in DC" ArcGIS layer (CRIMEID -> REPORTDATE, WARD):
https://maps2.dcgis.dc.gov/dcgis/rest/services/DCGIS_DATA/Public_Safety_WebMercator/MapServer/24/query

## Scope

- **Population**: person-rows where the rider's own `INVEHICLETYPE` indicates
  a scooter/moped. This counts injuries *to scooter riders*, not third parties
  (e.g. a pedestrian struck by a scooter) -- the schema has no way to identify
  that from a rider's own row.
- **Total scooter-rider person-rows**: 2927
  - `moped_scooter` (covers 2008-2022): 1692
  - `moped_or_motorized_bicycle` (covers 2023-2026): 1235
- **Severity split**: Fatal 14, Major 243, Minor 1355, None 1315

## Known data issues (do not silently ignore these)

1. **2023 coding-scheme seam.** DC's `INVEHICLETYPE` value for scooters/mopeds
   changed around 2023: `Moped/scooter` rows run 2008-2022 then stop entirely;
   `Moped or motorized bicycle` rows are near-zero through 2022 then take over
   from 2023 onward. Both are included here and tagged via `match_source` /
   `breakdown_match_source.csv` so this seam stays auditable. The 2023+ code
   is broader and may include some non-electric mopeds, so 2023+ counts may
   run slightly high relative to "true" e-scooter injuries.
2. **~2% of rows have no resolvable REPORTDATE.**
   DDOT's crash-location layer excludes crashes it couldn't geocode, so
   60 of 2927 rows fall back to a year-only date derived from the
   CCN case-number prefix (`date_source = ccn_year_fallback`). Use
   `timeseries_month_severity.csv` for month-level trend (covers the
   2867 resolved rows only) and `timeseries_year_severity.csv` when you
   need every row accounted for.
3. **Small-N severity bins.** Only 14 fatal rows total across the whole
   period -- do not read year-to-year wiggles in the fatal series as a trend.
4. **No scooter-share operator field exists anywhere in this data.**
   Operator-level slicing (Lime/Bird/Spin/etc.) is not possible from what's
   fetched here; it would require an external DDOT/operator-reported dataset.
5. **Counts are person-involvements, not unique crashes** -- a small number of
   crashes have more than one scooter-coded person (e.g. rider + passenger).
6. **Shared/dockless e-scooters still cannot be isolated from privately-owned
   or gig-delivery (DoorDash/Uber Eats-style) mopeds and scooters, even after
   the 2018-03 program-debut cutoff marked on the chart.**
   That marker is a hard floor (nothing before it can be a shared device --
   the program didn't exist), not a clean split going forward: `INVEHICLETYPE`
   is one blunt bucket covering shared-fleet devices, privately-owned kick
   scooters, and delivery-rider mopeds together, and no field in this data
   (including `LICENSEPLATESTATE`, which was tested and rejected -- it's
   noisy/inconsistently coded across years and "no plate" rows already appear
   throughout 2008-2016, before shared scooters existed) can split them apart.
   This confound is worst in exactly the 2020-2026 window this analysis cares
   about, coinciding with pandemic-era gig delivery growth.
7. **Ride Report's historical numbers are unreliable before 2021-Q4.**
   Cross-checked against DDOT's own published monthly ridership for the
   overlapping period: Ride Report captured only ~2% of DDOT's trip count in
   2019-Q1, rising to ~34% by 2021-Q1, ~88% by 2021-Q3, and ~99% by 2021-Q4.
   That's a data-coverage ramp-up (operators progressively onboarding to Ride
   Report's feed), not real ~90x ridership growth -- DDOT's own numbers show
   growth over that period was closer to 2x. Only 2021-Q4 onward is used
   anywhere in this analysis; earlier Ride Report quarters are kept in
   `data/reference/ride_report_quarterly_scooter_stats.csv` for transparency
   but marked `coverage_reliable=False` and excluded from every chart/aggregate.
8. **Chart starts at 2010-Q1, not the earliest data.** The full
   crash history has scattered points back to 2003 (2003-Q4, 2006-Q3, then a
   gap to 2008-Q2), with multi-year gaps between them -- not a real
   quarter-over-quarter series. 2010-Q1 onward has no gaps through the
   present, so the chart is clipped there for a clean, continuous x-axis;
   `timeseries_quarter_severity.csv` still has the full history back to 2003
   if you want it.

## Files in output/

- `person_level.csv` -- one row per scooter-rider person-record; the base
  dataset everything else rolls up from.
- `timeseries_quarter_severity.csv` -- primary time series for graphing
  (matches the chart's binning; same REPORTDATE coverage as the monthly file).
- `timeseries_month_severity.csv` -- finer-grained companion series, same
  ~98% REPORTDATE coverage, monthly instead of quarterly.
- `timeseries_year_severity.csv` -- coarsest, 100%-coverage companion series.
- `breakdown_age_band.csv`, `breakdown_impaired_speeding_ticket.csv`,
  `breakdown_ward.csv`, `breakdown_match_source.csv` -- other slicing
  dimensions found in the data.
- `quarterly_injuries_by_severity.png` -- stacked bar chart of the primary
  time series from 2010-Q1 onward (earlier quarters excluded --
  sparse, gapped reporting before then, see caveat 8 above), with the
  2018-03 program-debut quarter and the 2023
  coding-scheme seam both marked, and ridership overlaid (right axis) --
  DDOT's own series through 2022-Q1, Ride Report spliced on from 2022-Q2
  onward (reliable quarters only), each visually distinguished.
